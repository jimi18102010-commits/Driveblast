## 2024-03-24 - Prevent connection pool exhaustion on streaming requests
**Learning:** In applications using connection pooling (like `requests.Session`), streaming requests (`stream=True`) that are aborted or return early without consuming the entire content iterator will leave the underlying socket open. This leads to connection pool exhaustion and memory leaks over time, severely degrading application performance when handling multiple file downloads or encountering errors.
**Action:** Always ensure that HTTP response streams are explicitly closed using `resp.close()`. Add a `.close()` call on all early exit paths (like 401/403/404 errors), when reading intermediate HTML pages instead of streams, and within a `finally:` block around the main streaming download loop to guarantee resource release even on exceptions like `KeyboardInterrupt`.
